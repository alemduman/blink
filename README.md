# Blink: автопостинг Reels в Instagram через GitHub Actions

Видео (и описание) кладёшь в папку `queue/`. В назначенное время GitHub берёт самое старое видео, выкладывает его на GitHub Pages (публичная ссылка) и публикует в Instagram как Reel. После успешной публикации файлы переезжают в `posted/`.

Работает так же, как автопостинг Битвы флагов: токен системного пользователя Meta, защита от дублей и опоздавших запусков, запуск от cron-job.org.

## Как класть видео

В `queue/` через Add file → Upload files:

    2026-11-01-shade.mp4   видео (обязательно)
    2026-11-01-shade.txt   описание с хэштегами (по желанию)
    2026-11-01-shade.jpg   обложка (по желанию)

Имена начинаются с даты: публикуется первое по алфавиту. Можно загрузить сразу много. Хэштегов Instagram принимает не больше 5; если в `.txt` больше, лишние убираются автоматически. Если видео не в H.264/AAC, оно перекодируется само.

## Настройка

1. **Аккаунт Instagram:** профессиональный (Creator или Business), привязан к странице Facebook.
2. **Meta Business Suite:** добавить аккаунт в то же бизнес-портфолио (Настройки → Аккаунты → Аккаунты Instagram), затем Системные пользователи → `flagbattle-poster` → Добавить объекты → новый аккаунт Instagram с полным управлением.
3. **ID аккаунта Instagram** (число, начинается на 17841): Graph API Explorer → запрос `me/accounts?fields=instagram_business_account{id,username}` с токеном системного пользователя.
4. **Секреты** (Settings → Secrets and variables → Actions): `IG_TOKEN` (тот же токен системного пользователя, что и в Битве флагов), `IG_USER_ID` (ID нового аккаунта).
5. **GitHub Pages:** Settings → Pages → Source: **GitHub Actions**. Репозиторий должен быть публичным.
6. **Проверка:** Actions → Blink autopost → Run workflow (галочка «Проверка» стоит). Положи в `queue/` тестовое видео заранее: в логе будет «Доступ к Instagram проверен».

## Расписание

`config.json` → `schedule.hours` (часы по Баку, сейчас `[10,12,14,16,18,20,22]`, минута `7`). В `.github/workflows/autopost.yml` строка `cron` должна совпадать по часам, но в UTC (Баку = UTC + 4; 20:07 = 16:07 UTC). Запуски повторяются каждые 15 минут внутри слота, дубли пропускаются.

Чтобы постить, например, в 12, 16 и 20: `"hours": [12, 16, 20]` и в cron `7,22,37,52 8,12,16 * * *` (часы в UTC = часы по Баку минус 4).

Опоздавший больше чем на `maxDelayMinutes` (90) запуск пропускается. Если предыдущий ролик вышел меньше `minGapMinutes` (50) назад, повторный запуск ничего не делает. Пауза: `"autoPublish": false`.

## Запуск минута в минуту (cron-job.org)

Расписание GitHub иногда опаздывает или теряется. Надёжнее запускать извне: cron-job.org отправляет POST на
`https://api.github.com/repos/<логин>/<репозиторий>/actions/workflows/autopost.yml/dispatches`
с заголовками `Authorization: Bearer <токен Fine-grained, Actions: Read and write только на этот репозиторий>`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28` и телом
`{"ref":"main","inputs":{"dry_run":"false","source":"cron"}}`.

## Если что-то не так

- **Очередь пуста:** запуск пишет это в Summary и ничего не делает.
- **Ошибка кода 190:** токен недействителен, обнови секрет `IG_TOKEN`.
- **Ошибка кодов 10/200/283:** у системного пользователя нет доступа к новому аккаунту Instagram (шаг 2).
- Письма о сбоях приходят от GitHub на почту.

## Автогенерация роликов

Если в `queue/` пусто, перед публикацией ролик делает само приложение (`app/studio.html`, исходники в `app/src`) в headless Chromium на GitHub Actions:
- тест выбирается с ротацией (не повторяется из последних 8), фон — из 6 тем без повторов подряд (не из последних 4);
- сложность Expert, максимум раундов в пределах ~58 секунд, битрейт 30 Мбит/с, финальное кодирование H.264 crf 14 + AAC;
- подпись на английском, не больше 5 хэштегов;
- настройки: `config.json` → `generate`; выключить: `"enabled": false`.
Ролики, положенные в `queue/`, публикуются первыми.
Пересборка приложения после правок в `app/src`: `python3 app/build.py`.
